# First Windows bench of Settings — findings and fixes

*2026-11-03. The owner ran the merged Settings work (PRs #1–#3, main 59855ec)
on Windows for the first time. Four things came back; the first turned out
to be a planner bug, the other three are design.*

## What came back

1. **"It wants to sync 101 albums — it already has the 101."** A dry run
   from the command line showed every one of the 907 tracks flagged
   `modified 1h0m0s after the copy on the device`. Exactly one hour: the
   clocks went back on the night of 2026-11-01. FAT stores local time, and
   Windows converts a FAT timestamp to UTC with the offset in force *now*,
   so after a daylight-saving change every file on the iPod reads an hour
   older (or newer) than it did when it was written. The source files are
   on NTFS, which stores UTC, so they did not move. The planner's two-second
   slack then calls all of them changed, and a sync would push 20 GB over
   USB to change nothing. The CLI dry run is the only place the reason was
   visible; the window said "Sync 101 albums" and nothing else.
2. **The Settings sheet's sections blur together.** Six headings in the
   same small muted type, rows on identical plates, and nothing that says
   what a section is *for*. "Small covers" in particular says what it
   measures and not why anyone would change it.
3. **Browse… opens a PowerShell console.** The picker is a PowerShell
   one-liner (`internal/app/picker.go`), and a windowsgui process that
   starts a console program gets a console window flashing up before the
   dialog. The owner's ask: a chooser inside the app, no shelling out.
4. **No breakdown of what a sync will do.** The preview lists albums and
   track counts, but not *why* each is going (new, changed, renamed), nor
   the rest of the plan (covers, playlists, index, what is on the iPod and
   not in the folder).

## Slices

Each is its own branch and PR off `main`, squash-merged, same gates as
every slice: `go build ./... && go vet ./... && go test -tags noaudio ./...`,
the `-tags novulkan` build, `gofmt -l` empty, `TestNoOldWordsOnTheFront`
reads any new front strings, and a canned state for anything new on screen.

### D0 — the hour (planner)

`syncer.unchanged` and `syncer.sidecarsStale` accept a difference that is
exactly one hour (±`MTimeSlack`) as the same time: `|d| ≤ slack` or
`||d| − 1h| ≤ slack`. The reason string says so ("same size; the time
differs by one hour, a daylight-saving shift on the iPod's FAT volume")
so a dry run shows it was considered. `--verify` is unaffected (content,
not time). Tests: a destination an hour older and an hour newer both skip;
an hour and five seconds still copies; the sidecar case the same. The guide's
sync paragraph gains one sentence.

The CLI prints the plan, so a user who has the problem can see it; the
window could not, which is D2.

### D1 — the chooser (in-app folder and file browser)

`internal/app/chooser.go`: a sheet with the album sheet's chrome (scrim,
plate, Esc and a click outside cancel) that replaces every call into
`picker.go`. `picker.go`, `PickerAvailable`, `pickerOK` and the
PowerShell/osascript/zenity commands go; `picker_test.go` becomes the
chooser's tests. Every Browse… stays enabled.

- **Modes.** Folder (music folder, playlists folder, backup folder, log
  folder) and file (firmware image `*.ipod;*.bin`, genre map `*.json`). A
  `chooserKind` carries the title, the mode and the file filter — the
  `fileKind`/prompt constants today.
- **Layout, top to bottom.** The title (the prompt: "Choose the music
  folder"). A path line: the current folder as clickable crumbs
  (`This PC › C: › Users › you › Music`), with an editable field behind a
  *Type a path* link for people who have one on the clipboard (Enter goes
  there; a path that is not a folder shows a muted line under the field and
  stays). The list. The foot: a muted line that says what is selected, then
  *Cancel* and the choose button.
- **Roots.** Windows: *This PC* lists the drives (every letter whose root
  `os.Stat`s, with the volume label from `windows.GetVolumeInformation` —
  `golang.org/x/sys/windows` is already a dependency — shown as
  `Local Disk (C:)` / `BRANDON'S I (D:)`; the label is read on the list
  goroutine, never per frame). Linux/macOS: `/` and the home folder as the
  two roots. The chooser opens in the field's current path when that is a
  folder, else the last folder chosen in this run for that kind, else the
  home folder.
- **The list.** Folders first, then files (folder mode lists folders only),
  each group sorted case-insensitively. Hidden entries are skipped: a
  leading dot, and on Windows the hidden or system attribute (read through
  `x/sys/windows` from the `os.DirEntry`'s `Sys()`; `$RECYCLE.BIN` and
  `System Volume Information` are skipped by name as well, they are
  attributes most of the time but not on every volume). Each row: a drawn
  glyph (a folder outline for folders, a page for files — `drawMark`-style
  clip paths, no icon font, both palettes), the name, and for files the
  size in the right column. One click selects a row; a second click on a
  selected folder, or Enter, enters it; Backspace or the *Up* crumb goes
  up; arrow keys move the selection; Esc cancels. Rows are 26 dp and the
  list is a `widget.List` so it scrolls; the sheet is 560 dp wide at most
  (94% of the window below that) and 80% of the window's height.
- **Reading a folder** is a job on its own goroutine (an iPod or a network
  drive can take seconds to list): the sheet shows "reading…" on the path
  line meanwhile, and the result lands through the mutex-and-drain pattern
  every other result uses (`u.newChooserDir`), keyed by a sequence number
  so a slow answer for a folder the user already left is dropped.
- **Choosing.** Folder mode: the button says *Choose this folder* and
  returns the current folder, or, when a folder row is selected, *Choose
  "Name"* and returns that one. File mode: *Choose* is enabled only with a
  file row selected. The answer goes where the picker's did: `setSource`,
  `newPath`/`pathFor` for flash and install, `applyPicked` for the three
  Settings paths, `setBackupDir` for the backup folder — the callers keep
  their shape, only the function that asks changes.
- **Canned.** `--dialog chooser` renders the sheet over the demo state
  with a fixed, fake listing (no disk reads in a canned state) so it can be
  reviewed in both palettes; `shots.go` adds it to the screenshot set if
  the set is enumerated there. Its strings join `settingsStrings` or a
  `chooserStrings` that `frontStrings` reads.
- **Tests.** The pure parts: roots per GOOS, the sort and the hidden
  rules on a temp tree, file filters, crumb splitting for `C:\Users\you`
  and `/home/you`, the choose button's label in each state, and a
  `NewUI`-level test that a chosen folder reaches `st.Source` through
  drain.

*Show folder* buttons keep using the shell (`openFolder`, Explorer); that
opens no console.

### D2 — the preview says why

- `syncer.FileOp` gains `Why CopyWhy` (`json:"why"`): `WhyNew`
  (not on the device), `WhySize`, `WhyTime`, `WhyContent` (`--verify`),
  `WhyUnreadable`, and `WhySame` for skips, `WhyHourShift` for D0's skip.
  Set beside `Reason` wherever `Reason` is set. `AlbumsFromPlan` counts
  `New` and `Changed` per `Album` (a changed album is one with a copy whose
  Why is not WhyNew), and `Renamed`.
- The plan has one printer: `printPlan` moves from `internal/cli/sync.go`
  to `syncer.WritePlan(w io.Writer, p *Plan, listSkips bool)`; the CLI
  calls it, and so does the preview.
- `previewDialog` becomes: title *Preview: N albums to copy*; a labelled
  card (the write dialog's `card` shape) with one line per kind of work,
  only the lines that apply — *New on the iPod* "3 albums · 31 tracks ·
  1.2 GB"; *Changed since the last sync* "2 albums · 4 tracks · 90 MB";
  *Renamed on the iPod* "1 track"; *Covers to render* "5 albums";
  *Playlists* "2 to write"; *Index* "rewritten, 907 songs" or "unchanged";
  *On the iPod, not in your folder* "4 albums stay (Sync and remove deletes
  them)" — then the album list as today with the mid column saying the
  why: "all 11 tracks · new", "3 of 10 tracks · changed"; then *Show the
  plan* (the dialog's existing `plan` link and mono box) holding
  `WritePlan`'s text. The `note` line stays.
- When nothing would be copied but the plan still has work (covers,
  playlists, a changed index), the dialog is *Nothing to copy* with the
  card showing that work and a *Sync* button; only when there is no work
  at all is it *Everything is on the iPod* with Close.
- `--dialog preview` stays the canned state and gains the card; words
  test; tests for the Why values, the album counts and the dialog's lines
  for a new-only plan, a changed-only plan, a no-copy-but-covers plan and
  an empty plan.

### D3 — the sheet reads as sections

- Each section is a card: the heading in `Ink` SemiBold at 13 sp with one
  muted sentence under it that says what the section is for, then its
  rows' plate, then 14 dp of air. The six sentences:
  Library — "Where your music is, and what Fix all is allowed to change in
  it." Sync — "How copies to the iPod are checked and what happens after."
  Firmware — "Backups taken before a flash, and how the app learns about
  releases." Playback — "Playing albums on this computer." Appearance —
  "The window." Diagnostics — "For sending a log with a bug report."
- *Small covers* is renamed *Low-resolution covers* and its sub-line says
  what it is for: "a cover smaller than this on its shorter side is
  low-resolution: the Fix tab lists it and Fix all replaces it with a
  larger one. The iPod draws covers at 120 px, so this is about your music
  folder, not the iPod." (`coreart.ArtSize` is 120.)
- Row labels that are nouns without a verb get their sub-line checked for
  the same question — "what happens if I change this" — and the ones
  that do not answer it are reworded: Duplicates ("the Fix tab lists
  albums whose songs are also in another folder"), Copies (the Verify
  sub-line already does; Eject gains "so the cable can be pulled as soon
  as the copy ends"), Keep backups ("a flash backs the whole firmware
  partition up first; this is how many of those to keep"), Check for
  updates ("asks GitHub once, when an iPod connects"), Theme ("System
  follows Windows' light or dark apps setting"), Window (the two ticks are
  self-explaining), Log file ("the window's log, appended to this file").
- The footer sentence stays. GUIDE.md's Settings paragraph is reread
  against the new words (`Small covers` → `Low-resolution covers`).
