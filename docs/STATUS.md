# Status — every command, and what is behind it

The short version is in the [README](../README.md); this is the long one, a row per
command with what it does, what it refuses and why. The phase letters (S2, L5…) are the
plans in [design/](design/).

| Command | State |
|---|---|
| `firmware pack` | **works** — wraps a raw image in the `.ipod` format. the firmware repo's `core/Makefile` `ipod` target runs it on every build, so this is the one command a broken change actually breaks. Validates its input, writes atomically, verifies by read-back. |
| `firmware unpack` | **works** — extracts and checksum-verifies an image. `--ignore-checksum` for recovery. |
| `build hw` / `build sim` | **works** — thin wrapper over `make -C core <target>`. |
| `info` | **works** (S6) — identifies the connected iPod and describes it: disk/model/serial/size, the logical sector size (from the OS, cross-checked against where the Apple preamble actually is), the partition table, the image directory with a fresh checksum per image, and the OSOS length/capacity/checksum, and a `firmware:` line naming the installed build from the `CORE-FW-VERSION:` marker in the OSOS body (S8; images before v0.1.3 carry none and report "unknown"). `--json` for machines, `--all-disks` to list every disk the OS can see. Read-only. |
| `index` | **works** (S2) — build `CORELIB.IDX` in Go, byte-identical to `tools/build_index.py` |
| `art` | **works** (S3) — `folder.art` (120×120) and `folder.thm` (28×28) CART sidecars, from a FLAC's embedded cover, one album or a whole tree. |
| `art --fetch` | **works** (L4) — finds cover art for albums that have none: the iTunes Search API first, then MusicBrainz + the Cover Art Archive (mandatory User-Agent, one request a second, the Cover Art Archive hop included). Candidates are printed with a match score — 1.00 artist and album equal, 0.90 equal once `(Deluxe)`/`- Single`/`[Remastered]` are stripped, 0.70 containment, under 0.50 a name mismatch — and the score is taken at the WEAKER of the two fields, so the right album by the wrong artist is never accepted. Nothing is written without `--write`, which asks per album unless `--yes`, and `--yes` accepts only at or above `--min-score` (0.9). An accepted cover is validated (JPEG or PNG, at least 300 px, at most 10 MB), embedded in EVERY FLAC of the album through `flac.WritePicture`, written beside them as `cover.jpg` and baked into the two sidecars. `--dry-run` decides and writes nothing. Images are cached under `<user cache dir>/core/art` (and a "no match" is remembered for a week); they belong to their rights-holders and are never written anywhere but your files and that cache. |
| `organize` | **works** (L2) — the source tree's names, made to say what the tags say: `Album - Artist/[Disc N/]NN - Artist - Title.flac`, which is the convention the device locator is derived from (`library.ScanTree` reads `NN. Title.flac` off the byte-sorted folder listing, so zero-padded track numbers put `pos` on the track number and `TrackTitle` hands the tag title back). Nothing is guessed: a file missing album, artist, title or a usable track number is listed under "needs attention" and left alone, an album whose artist tags cannot agree is a question, two files claiming one track number are both left, and a name already held by a different file is never overwritten. A difference only a curly apostrophe deep is NOT a rename — the locator hash folds it, so the rename would be a whole-album re-copy for nothing. `folder.art`/`folder.thm`/`cover.*` follow their album when the folder empties; every other file stays. The preview is the default and its last line is the cost in tracks the next sync will copy again. `--apply` fsyncs a full undo journal to `<user config dir>/core/journal/` BEFORE the first rename and stops at the first failure with that journal intact; `--undo <journal>` replays it backwards, refusing any file whose size or mtime changed since; `--list-journals` finds them. |
| `fix` | **works** (L5) — one command for everything wrong with a library, and the one job that fixes it. The report (the default; it writes nothing and asks no service anything) lists albums whose first track carries no cover, files misnamed inside the right folder, files that belong in another folder, and the files nobody can name from their tags — plus the cost: renamed tracks are re-copied on the next sync because the filename IS the device's locator, and the two byte totals are counted apart (already on the iPod vs never been there). `--art` is the flag that goes to the network: it prints the ranked candidates with the score `--yes` would act on. `--yes` does it — as ONE job with ONE undo journal: the covers go into every track of their album FIRST (embedding rewrites the file, and the journal records each file's size and mtime as it moves it, so a cover written after the rename would make that rename un-undoable), then the moves, then `folder.art` + `folder.thm` + `cover.jpg` in whatever folder the album ended up in. A cover that fails to download is one line in the summary, never a reason to abandon the renames. `--names`/`--organize`/`--art` narrow the job; `--dry-run` decides everything and writes nothing; `--json` is what the app reads; `--undo <journal>` puts the names back and says plainly that it does not remove embedded art. **Low-res art:** a cover under `--min-art <px>` (600; `0` turns the check off; the app's `min_art_px`) on its shorter side is listed under its own heading and goes through the same flow, with one rule — a candidate is used only when it is LARGER on its shorter side. The album folder's own `cover.jpg`/`folder.jpg` comes first when it is bigger (no lookup; `--dry-run` shows it as "replaced embedded 500×500 → cover.jpg 1400×1400"), and the same file is used, unasked, for an album with no embedded cover; otherwise the network candidates are downloaded to be measured. A replacement writes `<stamp>-fix.json` beside organizer's journals, with the old pictures and sidecars in `<stamp>-fix/`, so `--undo` puts the old cover back. **Duplicates:** two album folders whose tracks match by title, artist (`artfetch.NormKey`) and length (±2 s) — A in B when ≥ 90 % of A's tracks are in B, the same album when both ways, a `Disc N` folder part of its album, one-track folders ignored — are listed with a why-line and never changed by `core fix`; the app's *Keep this one* moves the other folder to `.core-trash/<timestamp>/` beside the music folder (a plain folder, not the Recycle Bin — the only pure-Go route is `SHFileOperationW` via syscall, untestable off Windows and with nothing Undo could restore from), journaled, so Undo brings it back. |
| `add` | **works** (L2) — `core add <folder> --to <music folder>` reads a folder from outside the library and prints the plan the window's *Adding to your library* sheet shows: the albums by their tags with the `Album - Artist` folder each gets, and the ones left out with the reason (no tags, no track numbers, a format the iPod cannot play, already in the library by folder or by the duplicate check's same-songs rule). Then it copies every file into place (never over one that is there), verifies each copy against its original by SHA-256, and only when every file of an album verified deletes the originals and their emptied folder (`--keep-originals` leaves them). A mismatch removes that album's copies and leaves its originals. Journaled (`<stamp>-fix.json`, format 3): `core fix --undo` puts the originals back, rebuilt byte for byte even when a cover went into the copies. `--to` defaults to `source` in `core config`; `--dry-run` prints the plan only. |
| `sync` | **works** (S4b) — source tree → device layout, art sidecars, playlists rewritten to device paths, `CORECFG.DAT`/`CORELOG.BIN`/`COREOTG.DAT` and the five `Music/Playlists/On-The-Go N.m3u8` slots created only when absent or invalid, `CORELIB.IDX` written LAST. The On-The-Go files are the device's, not the source tree's: an existing slot playlist is **never** rewritten (it may hold a list saved on the iPod, or a playlist of your own at that name), `--prune` keeps all five whether or not they exist, and a source playlist whose device name would be a slot name is refused with a warning rather than copied over one. Plans first: `--dry-run` prints the whole plan with byte totals and writes nothing. Skips a track whose size matches and whose time is within 2 s (`--verify` hashes instead). Re-renders an album's sidecars when they are missing, invalid OR older than the file the cover is read from, so embedding art with `core fix` reaches the iPod on the next sync with no flag (`--art-refresh` is still the force). Deletes nothing without `--prune --yes`. Refuses a drvfs/9p destination. **Sets the iPod's clock**: the host's time and zone go into `CORECFG.DAT`'s time block for the device to take at its next boot (it cannot be told the time on the cable — that is Apple's disk mode answering). One slot is rewritten and the other copied verbatim, with no truncation, so nothing the device owns is lost. |
| `eject` | **works** (S4b) — **stamps the clock first** (this is the freshest stamp there is: the device reboots when the cable comes out, and the boot that reads it is seconds later; a target that is not a mount point is skipped with one line, and a failed stamp never fails an eject), then flush, then dismount + eject. Windows: lock/dismount/allow-removal/eject through the volume handle, with Explorer's Shell verb as the fallback. Linux: `udisksctl unmount` + `power-off` (prints the commands when udisksctl is absent). macOS: `diskutil eject`. |
| `name` | **works** (L5b) — the iPod's name. `core name D:` prints the FAT volume label as it is stored, the disk serial and the friendly name core-app remembers for that serial; `core name D: "Brandon's iPod"` writes both halves — the label becomes `disk.LegalLabel(name)` (upper-cased, ASCII, at most the 11 bytes a FAT volume entry holds, so `Brandon's iPod` is stored as `BRANDON'S I` and the command says so), and the name itself goes into `<user config dir>/core/config.json` under `names`, keyed by the disk serial. The label is read back and compared; an empty name clears both; `--label-only` writes the volume and nothing else. Needs the same rights as any volume operation, and never during a flash — the flasher dismounts the drive letter. |
| `firmware inspect` | **works** — tells a partition dump, a `.ipod` file and a raw image apart and describes it: the image directory like `ipodpatcher -l` with a fresh checksum per entry, or the `.ipod` header, or the sum a raw image would need. Read-only. |
| `backup` | **works** (S6) — dumps the whole firmware partition (preamble, directory, every image) to a file, temp + fsync + rename, then re-parses the file it wrote to prove the backup is a backup. Never overwrites. Default path `<user config dir>/core/backups/fwpart-<bytes>-<timestamp>.bin`. Same bytes as `ipodpatcher -r`. |
| `firmware read` | **works** (S6) — writes exactly the OSOS entry's `Length` bytes (no padding to the 0x800 boundary), which is `ipodpatcher -rfb` byte for byte. |
| `flash` | **works** (S7) — replaces `ipodpatcher -wf`. Writes the OSOS body (zero-padded to 0x800) and the one directory sector holding its row, in that order; everything else on the partition is untouched. The row's entry point is set to 0 (this image starts at its first byte; Apple's starts 7.5 MB in, and a row left saying so is a device that boots to nothing) and `addr`/`vers`/`loadAddr2` are kept exactly as the device had them. Backs the WHOLE partition up first (temp + fsync + rename, then re-parsed off disk), locks the device, flushes, and re-opens it read-only to compare the read-back. `--dry-run` prints the plan and opens nothing for writing; without `--yes` you type the device path to confirm. `--from-backup <fwpart.bin>` is the recovery path: whole-partition restore, refused unless the file's preamble, directory and OSOS checksum all validate and its size matches the device. |
| `install` | **works** (L1) — one command for an iPod that is still running Apple's firmware: classifies the OSOS row and body (`fwpart.Classify`: a `CORE-FW-VERSION` marker means Core, no marker with entry point 0 and a body under a megabyte means a Core from before v0.1.3, anything else — Apple's `entry 0x736000` / 7.6 MB — means Core is not installed), refuses a device that is already ours with `core update` as the thing to run instead (`--force` overrides), downloads the latest release when no file is given, then runs the `flash` sequence unchanged. The whole-partition backup is named `apple-<serial>-<date>.bin` when what it holds is not Core, because that file is the only copy of that device's Apple firmware in existence — it is never pruned, and the install's last lines name it and the `core flash --from-backup` that puts it back. Afterwards it creates on the music volume what the firmware can overwrite but never create: `CORECFG.DAT`, `CORELOG.BIN`, `COREOTG.DAT`, an empty `Music\` and the five On-The-Go slot playlists inside it, and stamps the clock into the config it has just guaranteed exists, so the first boot after an install is not the one that reads "Not set". On Windows the elevated child is another `install` of the already-downloaded file, never a release tag. The sequence itself is `internal/installer` (L6), so the app's Install button runs the same one; what is left in the command is the flags, the download and the exit code. |
| `update` | **works** (S8) — compares the version marker in the installed image with the latest GitHub release, prints the release notes, downloads `core-<tag>.ipod` (or `core.ipod`) into `<user cache dir>/core/<tag>/`, verifies its `.ipod` transport checksum, and then runs the `flash` sequence unchanged. `--check` stops after the comparison and downloads nothing; `--tag vX.Y.Z` pins a release and is also how the installed version gets written again. On Windows the elevated child is re-invoked as `flash <cached file> --yes --no-relaunch`, never as `update`, so the process with Administrator rights does no network I/O. There is no signature checking: the checksum is an integrity check. |
| `config` | **works** (C2, C3) — reads and writes `<user config dir>/core/config.json`, the file core-app's *Settings…* writes: `core config` lists every known key with its value or `(default)`, `get`/`set`/`unset`/`path` do the rest. `set` checks the type and the allowed words and refuses unknown keys; every write goes through a raw-JSON round trip so keys this binary does not know survive, and lands by temp-and-rename. A flag always beats the file (and `$CORELIB_SRC` beats `source`); a command that takes a value from the file says so on stderr. Read by the CLI: `source`, `min_art_px`, `disc_folders`, `backup_dir`, `playlists_dir`, `genre_map`, `online_art` (off: `fix --art` refuses), `prereleases` (`update`/`install --prereleases`) and `keep_backups` (flash/update/install remove the older `fwpart-*` backups after the new one verifies; `apple-*` never). |
| `self-update` | **works** (library plan L6) — the newest `v…` release of this repository (`--prereleases` to include pre-releases): when it is newer than the running `core`, downloads this platform's `core-<os>-<arch>` and `core-app-<os>-<arch>` into `<user cache dir>/core/<tag>/`, checks each against the `<name>.sha256` published beside it (a binary without one is refused), and replaces this program and the `core-app` beside it — on Windows by renaming the running files to `core.old.exe` / `core-app.old.exe`, which the next start deletes. Asks first unless `--yes`. `--check` prints the comparison and what would be replaced, and downloads nothing. A bad checksum or a failed download replaces nothing; a folder this user cannot write is refused before the download, naming it and the release page. Does not restart anything; the window's *Update the app* does the same and restarts the app. |
| `doctor` | **works** (S8) — read-only walk printing one OK/WARN/FAIL line per check: device, tested hardware, the image directory, the OSOS checksum, the installed version, then the FAT volume — `Music/`, `CORELIB.IDX` (header, CRC, record count and the song/album/genre caps past which the device silently drops), `CORECFG.DAT`, `CORELOG.BIN` (header AND the block count against the file length, which is `evlog_mount()`'s own test), `COREOTG.DAT` (the On-The-Go live list: the two-slot region, the newest slot's sequence and how many tracks it holds), the **clock** (never stamped / a stamp the device has not booted to take, both WARN / applied, OK) and the playlist folder — including one line per On-The-Go slot, because every way those can be wrong is invisible on the device: missing (Save has one fewer slot), empty, N tracks, a **torn save** the device opens to "Playlist damaged", or a playlist of your own sitting at a slot name — and for the last two it prints the way out, because it is the only thing that ever will: the device never writes to a slot with no header, an interrupted save can leave one looking exactly like a file of yours, and only a person looking at the file can tell them apart, so the line says to delete it and re-sync. Then the **boot** section: the newest boot in `CORELOG.BIN` (its clock, the index refusal line if any, whether the session ended with a final flush), held against `COREFLSH.TXT`, the note every verified flash leaves on the volume (the written row and the log's newest boot id at that moment) — a newer boot id is a boot of the flashed image; firmware newer than v0.2.2 names its build in the log and that line outranks the note. Exits 1 if any check FAILs. `--volume PATH` checks a volume with no iPod attached; the device lines become SKIPs. `--boot` prints only the boot section and exits 1 while the iPod has an image it has not started — the bench check after a flash is: unplug, let it start, plug back in, `core doctor --boot`. |
| `core-app` (separate executable, `cmd/core-app`) | **works** (S10, L5b–L7, app pass A1–A7, the library plan) — native desktop window, Gio v0.8.0, minimum 720×520, in the device's Linen or Onyx (System follows Windows' dark mode; the choice is `theme` in config.json), Nunito embedded. Three launch phases and no Refresh button: **Looking** (no iPod — the mark, the disk-mode steps, and a poll of `disk.FindIPods` every 2 seconds, paused while a job runs, which also catches the unplug), **Core is not installed** (a stock iPod: three sentences and **Install Core** / **Install from a file…**), and **Ready**. The header is the mark, the iPod's name (the friendly name remembered under the disk serial, else the volume label, else the model) with its model, one status line (firmware · update state · free space), and ONE verb-first primary — *Sync 7 albums*, *Update to v0.2.2*, *Install Core*, *Eject* — with Eject and "···" beside it and a Cancel in its place while a job that can stop runs. The release check runs once per launch after the first poll that finds an iPod; Flash, Update and Install all end by reading the device back. **Library** is the music folder in the four views the iPod's own menu has — *Albums* (the grid: each album's own cover at the tile's device-pixel size, NEW/CHANGED chips from the last preview, the iPod's bouncing bars on the playing album), *Artists* (a tile per artist, a mosaic of up to four covers or Deezer's photo when Settings allows it, sorted as the iPod sorts), *Genres* (a row per genre with the name the iPod will show, through the sync's genre map) and *Songs* (a sortable, searchable table) — with *Add music…* beside the switch. A click on an album opens it: cover, facts, what the iPod has, the tracklist, *Edit…* (the tags in fields; Save writes them, renames to match, journaled for Undo) and a player. **Fix** is the music folder (the one place it is set, with the in-window chooser) and the problem list: misnamed files, folders to organize, missing and low-resolution covers with candidates, duplicate albums, multi-disc folders; **Fix all**, **Undo**, **Rescan**. **Summary** is seven rows — Name, Firmware, Last boot (whether the iPod started the image it holds, from `CORELOG.BIN`), Storage, Library on the iPod (the index, covers, playlists and device files as the iPod will read them; *Repair* is a sync through the preview), Hardware, Backups — and an **Advanced** disclosure with the disk path, OSOS entry, device files, CLI path, *Preview sync* / *Sync and remove…* and the image flash. The log is a drawer on every screen (··· → Show the log, Ctrl+L, or a failed job's status line) with two tabs: this window's log, and the iPod's own `CORELOG.BIN`, newest boot first, read only while nothing is writing. The "···" menu holds backup, flash an image file, read again, check for updates, show and copy the log, add music, open the music folder, *Update the app to vX.Y.Z* when one is out, *Settings…* (everything the app remembers, saved as it changes — the same `config.json` the CLI reads) and About. The footer is the music folder and, while a track is loaded, the player — cover, bars, track and time over the seek line, play/pause, next, the app's own volume (`volume` in config.json, a p² loudness curve) and ✕; each FLAC plays at its ReplayGain as the firmware applies it (`internal/player/rg.go`). **Gates:** a firmware write shows an identity card (name, model, serial, "Disk 2 (as Disk Management numbers it)", bytes written) and is confirmed by a two-second press-and-hold; hardware Core has not been tested on is refused by the app (`app.ErrUntested`), and `core flash`/`core install --untested-hardware` is the one way to write it. *Sync and remove* lists what it would delete and counts it on its button; a dialog's Cancel always means no. On Windows the manifest (`cmd/core-app/winres/winres.json`) requests Administrator at launch, so the window reads the raw disk and writes itself; an unelevated window runs `core.exe` elevated instead. `--screenshot`/`--state`/`--size`/`--tab`/`--view`/`--theme`/`--drawer`/`--dialog`/`--source` render one frame headless ([BUILD.md](BUILD.md)); `--no-detect` turns the poll off; `--log FILE` is how a window that never opened explains itself. **Every pane scrolls vertically, and that is asserted:** `widget.List`'s zero value is a horizontal list, and three lists once built without `Axis` handed their children a million pixels of width, which Gio's stroke flattener turned into 40 GB of allocation. `TestEveryListScrollsVertically` (reflection over every `widget.List` on the UI struct) and `TestFrameAllocationIsBounded` (256 MiB per rendered frame) keep it from happening again. |

Commands are registered only once they have code behind them, so
`core --help` never lists something that would return "not yet
implemented". There are no stubs left: `info` was the last one.
